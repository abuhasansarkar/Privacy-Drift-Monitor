# API Endpoints

Every HTTP endpoint in the product: **30 route files, 33 method handlers.**

Generated by reading `src/app/api/**/route.ts` directly. Where this file and the code
disagree, the code wins — re-derive with:

```bash
find src/app -name "route.ts" | sort
```

> **The two API roots were consolidated.** Everything the agency UI calls used to live at
> `/api/<area>` and now lives at `/api/v1/<area>`. The old paths are **gone**, not
> redirected. `/api/portal`, `/api/public`, `/api/webhooks` and `/api/health` stayed put —
> external systems hold those URLs (provider dashboards, the Docker `HEALTHCHECK`, the
> deploy gate), and a probe or a webhook is not a versioned API.

---

## 1. Authentication surfaces

Five independent schemes. Which one applies is decided by path, and the decision is made
in `src/proxy.ts` before the handler runs.

| Scheme | Applies to | Enforced by | Identity |
|---|---|---|---|
| **API key** | `/api/v1/*` (customer-facing subset) | `authenticateApiKey()` + `requireApiScope()` per handler | Agency, via `pdm_live_` key |
| **Clerk session** | `/api/v1/*` (agency-UI subset) | `requirePermission()` / `requireWebsiteAccess()` per handler | Agency user |
| **Portal session** | `/api/portal/*` | `getPortalSession()` per handler | Client contact (magic link) |
| **Webhook signature** | `/api/webhooks/*` | Svix / Stripe signature per handler | Third-party provider |
| **None (public)** | `/api/public/*`, `/api/health/*` | — | Anonymous |

### ⚠️ `/api/v1` now carries two credentials, and the proxy gates neither

`/api/v1(.*)` is in `PUBLIC_ROUTE_PATTERNS` (`src/lib/public-routes.ts`), so
`auth.protect()` does **not** run for it. That was always true for the key-authenticated
routes, which authenticate themselves. It is now also true for the agency-UI routes that
moved in — they authenticate themselves too (`requirePermission()` throws
`AuthenticationError` with no session, `src/server/auth/context.ts:70`), so they still fail
closed.

What the move did break is the **status code**. Eight of the moved handlers had no
`try/catch`, because `auth.protect()` used to reject the request before they ran; without
it, a thrown `AuthenticationError` becomes an unhandled 500 rather than a 401. All of them
now go through `src/app/api/v1/_lib/with-errors.ts`, which maps the error to the v1
envelope. `_lib` is an App Router private folder — it is not a route.

### ⚠️ Portal routes bypass Clerk deliberately

```ts
// src/proxy.ts:221-224
export default clerkMiddleware(async (auth, req) => {
  if (isPortalRoute(req)) return respond(req);   // ← short-circuits BEFORE protect()
  if (!isPublicRoute(req)) await auth.protect();
  return respond(req);
});
```

`/portal(.*)` and `/api/portal(.*)` are **not** in `PUBLIC_ROUTE_PATTERNS` and must not be
added. They short-circuit above `auth.protect()` because a client contact has no Clerk
account — the magic-link session (§6.10) is their only credential. Adding them to the public
list would change nothing today and silently remove the portal's own session check the day
someone reorders those two lines.

## 2. `/api/v1` — API key (customer-facing)

**9 handlers.** `Authorization: Bearer pdm_live_…`, SHA-256 hashed and looked up by hash
(`src/server/auth/api-auth.ts`). Scopes: `read`, `write`, `admin` (admin satisfies any).
Default on key creation: `["read", "write"]`.

Tenant scoping is real here — every query goes through `forAgency(auth.agencyId)`.

| Method | Path | Scope | Notes |
|---|---|---|---|
| GET | `/api/v1/websites` | `read` | `?limit` (1–100, default 50), `?offset`. Returns latest scan + active issue count. |
| POST | `/api/v1/websites` | `write` | SSRF-validated via `validateWebsiteUrl`; plan limit enforced. |
| GET | `/api/v1/websites/[id]` | `read` | 404 if not this agency's. |
| DELETE | `/api/v1/websites/[id]` | `write` | Archive (soft delete). |
| POST | `/api/v1/websites/[id]/scans` | `write` | **202** + `{ scanId, status: "QUEUED" }`. 409 if already running, **402** `PLAN_LIMIT_REACHED`. |
| GET | `/api/v1/scans/[id]` | `read` | Scan detail with issues. |
| GET | `/api/v1/issues` | `read` | `?websiteId` `?severity` `?status` `?limit` `?offset`. |
| GET | `/api/v1/reports` | `read` | `?websiteId` `?type` `?status` `?limit` `?offset`. |
| GET | `/api/v1/reports/[id]/download` | `read` | **Dual-auth — see §3.1.** `?json=true` → `{ url }`; else 302 to a 900 s signed URL. |

### Response envelopes

```jsonc
// list
{ "data": [ … ], "pagination": { "total": 0, "limit": 50, "offset": 0, "hasMore": false } }

// error
{ "error": { "code": "UNAUTHORIZED", "message": "Missing or invalid API key" } }
```

| Code | Status | Meaning |
|---|---|---|
| `UNAUTHORIZED` | 401 | Missing/invalid/expired key, or agency not `ACTIVE` |
| `FORBIDDEN` | 403 | Key lacks the required scope |
| `NOT_FOUND` | 404 | Absent, or belongs to another agency |
| `VALIDATION_ERROR` | 422 | Bad filter enum value |
| `PLAN_LIMIT_REACHED` | 402 | Entitlement exhausted |
| `CONFLICT` | 409 | Scan already running |
| `BAD_REQUEST` | 400 | Malformed body |
| `INTERNAL_ERROR` | 500 | Unhandled |

## 3. `/api/v1` — Clerk session (agency UI)

**12 handlers.** Called by our own React app. Each names the permission it needs; none
relies on the proxy.

| Method | Path | Permission | Notes |
|---|---|---|---|
| POST | `/api/v1/ai/generate` | `ai:generate` | Zod discriminated union on `kind`. Delegates to the same Server Action the UI calls — no duplicated logic. |
| POST | `/api/v1/ai/feedback` | *(action-checked)* | Zod-validated; tenant check lives in `submitAiFeedback`. 204 on success. |
| POST | `/api/v1/billing/checkout` | `billing:manage` | Returns Stripe-hosted `{ url }`. |
| GET | `/api/v1/billing/confirmation` | `billing:read` | Polled after checkout; reads our projection, which only the signed webhook writes. |
| POST | `/api/v1/billing/portal` | `billing:manage` | Stripe customer portal `{ url }`. |
| GET | `/api/v1/search` | *(agency ctx)* | `?q`. Command palette. |
| GET | `/api/v1/settings/audit/export` | `settings:read` | Audit log export. |
| GET | `/api/v1/websites/export` | `website:read` | Website list CSV. Static segment — takes precedence over `[id]`. |
| POST | `/api/v1/websites/validate` | `website:create` | SSRF pre-flight on a submitted URL. |
| GET | `/api/v1/websites/[id]/evidence/export` | *(website access)* | `?format=csv\|json` (default csv), `Content-Disposition: attachment`. |
| GET | `/api/v1/websites/[id]/scans` | *(website access)* | Scan list for the report wizard. **Shares a file with the key-authenticated POST.** |
| GET | `/api/v1/scans/[id]/progress` | `scan:read` | Live scan progress. |

`requireWebsiteAccess(websiteId)` resolves the agency **and** asserts the website belongs to
it — the per-resource check, not just the per-route one.

### 3.1 The one true collision: `GET /api/v1/reports/[id]/download`

Consolidating the roots put the agency UI's report download and the customer-facing one on
the same path **and** the same method. It is now a single handler that accepts either
credential:

1. `authenticateApiKey()` is tried **first** — a caller that sent a Bearer token meant to
   use it.
2. A Bearer header that fails to authenticate returns **401**; it does not fall through to
   the session cookie. Otherwise a revoked key would be answered with someone else's
   session.
3. With no Bearer header at all, `requirePermission("report:read")` runs.

Whichever answers supplies the `agencyId`. Neither check is skipped because the other
exists. Behaviour preserved from both originals:

| Query | Effect |
|---|---|
| `?disposition=inline` | 300 s signed URL (the PDF viewer embeds it) instead of 900 s |
| `?json=true` | `{ data: { downloadUrl, expiresInSeconds, … } }` instead of a 302 |
| `Accept: application/json` | JSON — **only for key callers**, so the UI's `<a href>` and `<iframe src>` still get their 302 |

The audit row is written only on the session path, where there is a `userId` to attribute
it to — matching the pre-merge behaviour exactly.

## 4. Client portal API

**2 handlers**, split by credential.

| Method | Path | Auth | Notes |
|---|---|---|---|
| POST | `/api/portal/auth/request` | **None** | Magic-link request. Rate limit **5 / hour** per email *and* per IP hash. |
| GET | `/api/portal/reports/[reportId]/download` | Portal session | Scoped by `agencyId` **and** `clientId`. |

### ⚠️ Two deliberate information-hiding choices

- `/api/portal/auth/request` **always returns 204** — unknown address, revoked contact and
  rate-limited all look identical. A 429 here would confirm an address exists.
- The report download returns **404, never 403**. A 403 confirms the id exists.

## 5. Public / unauthenticated

**6 handlers.** Anonymous callers, so every one carries an abuse control.

| Method | Path | Abuse control |
|---|---|---|
| POST | `/api/public/free-scan` | Turnstile token + IP **3/h**, IP **10/day**, domain **1/day**, plus a blocklist (admin + automatic after 3 consecutive failures) |
| GET | `/api/public/free-scan/[token]` | Unguessable token; **404 on expiry, not 410** |
| POST | `/api/public/free-scan/[token]/email` | Token-addressed |
| POST | `/api/public/contact` | Rate limited in service → 429 |
| POST | `/api/public/analytics` | `checkRateLimit` per IP |
| POST | `/api/portal/auth/request` | *(see §4)* |

Free-scan status codes are deliberate: `RATE_LIMITED_IP` and `RATE_LIMITED_DOMAIN` are both
**429 with `Retry-After`**.

## 6. Webhooks — signature only

**3 handlers.** No session; the signature *is* the authentication. All three **fail closed**
when their secret is unset.

| Method | Path | Verification | No-secret behaviour |
|---|---|---|---|
| POST | `/api/webhooks/clerk` | `verifyWebhook()` (Svix), reads `CLERK_WEBHOOK_SIGNING_SECRET` | Bad signature → **400**, no retry |
| POST | `/api/webhooks/resend` | Hand-rolled Svix HMAC over `svix-id`/`svix-timestamp`/`svix-signature` | **401** if `RESEND_WEBHOOK_SECRET` unset |
| POST | `/api/webhooks/stripe` | `stripe.webhooks.constructEvent` over the **raw body** | **401** if `STRIPE_WEBHOOK_SECRET` unset; bad signature → 400 |

### ⚠️ Stripe reads the raw body first

`constructEvent` verifies a signature over the exact bytes Stripe sent. Call
`await req.json()` first and the signature can no longer be checked. Do not reorder.

## 7. Health probes

| Method | Path | Touches dependencies | Status |
|---|---|---|---|
| GET | `/api/health` | **No — on purpose** | Always 200 |
| GET | `/api/health/ready` | Postgres, Redis, object storage | 200 `ok`/`degraded`, **503** `unready` on fatal failure |

Liveness checks nothing: if it checked Postgres, a database blip would make the platform
kill healthy web containers, turning a degraded read path into a full outage.

Neither sets `dynamic = "force-dynamic"`. Route Handler `GET` is uncached by default in
Next 16 — adding it would be cargo cult.

## 9. Review findings

Things worth fixing, ordered by how much they cost. None of these break a gate today.

### 9.1 `/api/v1/*` has no rate limiting at all — HIGH (widened by the consolidation)

`grep -rn "checkRateLimit\|X-RateLimit\|Retry-After" src/app/api/v1` returns **nothing**.

Every other anonymous-or-scriptable surface in the product is limited — the free scanner has
four separate limits, portal magic links have two, analytics has one. The public API, which
hands out a long-lived `pdm_live_` bearer token and exposes `POST /websites/[id]/scans`
(a browser launch, the most expensive operation the product has), has none.

`AGENTS.md` states the API convention as "documented rate limits". Neither half exists.
The only backstop is the entitlement check inside the enqueue path, which returns 402 —
that caps billable scans, not request volume.

### 9.2 `?limit=abc` returns 500 instead of 422 — HIGH

```ts
// src/app/api/v1/websites/route.ts:29  (and issues, reports — identical line)
const limit = Math.min(Math.max(1, Number(url.searchParams.get("limit") ?? 50)), 100);
```

The clamp does not reject a non-numeric value, it propagates it:

| `?limit=` | result |
|---|---|
| *(absent)* | `50` ✅ |
| `50` | `50` ✅ |
| `-5` | `1` ✅ |
| `999` | `100` ✅ |
| `""` | `1` ✅ |
| `abc` | **`NaN`** ❌ |

`Math.max(1, NaN)` is `NaN`, and `Math.min(NaN, 100)` is `NaN` — the clamp passes it
straight through to `take`. Prisma rejects that:

```
take=NaN → THROWS PrismaClientValidationError
take=50  → OK, rows: 16
```

Whether the caller sees a crash or an envelope depends on which endpoint they hit:

| Endpoint | `try/catch` around the query | `?limit=abc` |
|---|---|---|
| `GET /api/v1/websites` | none (all three `try` blocks are in `POST`) | unhandled → **500** |
| `GET /api/v1/issues` | none | unhandled → **500** |
| `GET /api/v1/reports` | yes, line 86 | handled → controlled 500 |

All three should be **422 `VALIDATION_ERROR`** — the same code these routes already return
for a bad `severity`. A caller cannot tell a malformed parameter from an outage.

### 9.2b v1 does not use Zod — MEDIUM

`AGENTS.md`: *"Every input validated by a Zod schema before business logic runs."*

The v1 routes validate enums by hand instead:

```ts
// src/app/api/v1/issues/route.ts:45-56
const severityParam = url.searchParams.get("severity");
if (severityParam && !SEVERITIES.includes(severityParam as (typeof SEVERITIES)[number])) { … }
…
...(severityParam ? { severity: severityParam as Severity } : {}),
```

That part works and returns a correct 422. But note the shape: the value is tested behind an
`as` cast and re-cast on use. The cast is what makes it typecheck, and a cast is exactly what
stops being true when `SEVERITIES` and the Prisma enum drift apart. §9.2 is the same root
cause one field over — hand-rolled parsing that covers the cases someone thought of.
`schema.safeParse` would have covered `limit` without anyone thinking about it.

### 9.3 Scaffold endpoints ship to production — RESOLVED

Both files were deleted from the working tree (see §8). Commit the deletion to close it.

### 9.4 Error envelopes are converging, not converged — LOW

`/api/v1/*` returns `{ error: { code, message } }`. The five agency routes that already had
their own `try/catch` before the move — `ai/generate`, `ai/feedback`, `billing/checkout`,
`billing/confirmation`, `billing/portal` — still return the flatter `{ error: code }` shape
from `toAppError`. The six wrapped by `_lib/with-errors.ts` now emit the v1 shape.

So one path prefix currently answers with two envelope shapes depending on which handler you
hit. Worth flattening the five onto `withApiErrors` next; nothing depends on the old shape
except their own callers, which read `error` as an opaque code either way.

## 10. Verified during this review

Things that look like defects and are not — recorded so the next reviewer does not re-open them.

- **Portal routes bypassing Clerk** is correct (§1). A client contact has no Clerk account.
- **`/api/ai/feedback` having no route-level auth** is correct. It delegates to
  `submitAiFeedback`, which owns the tenant check. A second gate here would be a second
  place for the two to drift — the exact defect `AGENTS.md` records for white-label.
- **All three webhooks verify signatures** and fail closed with no secret.
- **`/api/health` touching no dependencies** is deliberate, not an oversight.
- **v1 tenant scoping is real** — every handler uses `forAgency(auth.agencyId)`, and
  returns 404 (not 403) for another agency's resource.
